## 開発の進め方

すべての開発変更は規模にかかわらずチケットにし、実装前にオープンチケット一覧へ登録する。新規チケットは [`tickets/TEMPLATE.md`](tickets/TEMPLATE.md) を使い、作業範囲・確認可能な受け入れ条件・テスト計画・fixture・実行証跡を記録する。チケット処理手順は [`process-ticket Skill`](../skills/process-ticket/SKILL.md) を参照。

1. 着手するチケットの依存関係と受け入れ条件を読む。
2. チケットと一覧を「作業中」に更新する。
3. 要求の変更は requirements.md、設計変更は関連設計書にも反映する。
4. 実装し、受け入れ条件に対応する確認を行う。
5. 変更点・確認結果・残課題をチケットに記録する。
6. 完了条件を満たしたものを「完了」にし、一覧も更新する。

1チケットにつき目的を絞る。大きくなれば子チケットへ分割する。チケットごとに変更をコミットし、コミットやPRにはチケットIDを付ける。外部チケットサービスへ移す場合はリンクと正本の所在を明記し、状態を二重管理しない。
