# T-047: Include vocabulary with no answer history in short-history plans

- Status: In progress
- Priority: P1
- Requirements: FLOW-001, SELECT-001
- Dependencies: T-045, T-046

## Background

The study-set option for including fewer than N historical answers currently requires at least one answer. Categories with no answers therefore remain empty even when the user explicitly asks to include words with insufficient history.

## Scope

- Included: Treat zero-answer vocabulary as having fewer than N answers when the option is enabled; apply accuracy ceilings only when at least one answer exists; clarify the option's UI wording.
- Excluded: Changing ordinary vocabulary practice filter semantics or inferring ratings for words with no answer history.

## Acceptance criteria

- [x] With N and insufficient-history inclusion enabled, zero-history vocabulary is eligible, including under an accuracy ceiling because accuracy is undefined without answers.
- [x] With insufficient-history inclusion disabled, zero-history vocabulary remains excluded by an N-answer filter.
- [x] Category and direction remain respected for words with recorded history.
- [x] UI wording clearly says words with no history are included when this option is enabled.

## Implementation

Study-set selection now treats zero answer events as insufficient history when the option is checked. Accuracy ceilings are applied only when at least one directional answer exists. Updated the label and helper text to make the zero-history behavior explicit, documented the rule in `docs/interaction.md`, and covered an answer-free category in integration and Playwright tests.

## Limitations
