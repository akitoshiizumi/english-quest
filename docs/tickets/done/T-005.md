# T-005 双方向の語彙学習と履歴保存

- 状態: 完了
- 優先度: P1
- 要求ID: VOC-001, LOG-001, UI-001
- 依存: T-002, T-003

## 目的・実装範囲

双方向の語彙学習と履歴保存を実現し、関連要求を満たす。

## 受け入れ条件

- [x] 語義・方向を選んで出題し、答え表示と自己評価後に次問へ進める。
- [x] A/UとS/Iおよびボタン操作がinteraction.mdに従う。
- [x] 語彙・語義ID、方向、自己評価、回答時間、セッション、UTC日時を保存する。
- [x] 入力中・IME・長押し・二重送信・保存失敗を確認し、失敗時に回答を失わない。

## 必須のテスト確認

- 統合テスト: 実行コマンド、結果、影響を受ける経路を記録する。機能変更では必須。
- E2Eテスト: 受け入れ条件に対応する画面操作シナリオ、実行コマンド、結果を記録する。画面を通る変更では必須。
- 該当しないテスト層があれば、その理由を記録する。
- テストデータ: 使用・追加したfixtureと期待値を記録する。実データ・実APIを使わない。
- テスト未実施や失敗がある間は完了にしない。[テスト方針](../../testing.md)を参照。

## 実装結果

方向選択、語義に結びついた出題・答え、自己評価、UTC回答イベントとセッションを実装。キーとボタンの両方を同一操作へ接続した。DB idempotency keyで二重送信を拒み、保存失敗では答えを隠さず再試行可能。

## 確認結果

`npm test` — HTTP/DB統合13件（当時）、キー単体3件、Playwright E2E3シナリオ成功。英日・日英、A/UとS/I、マウス操作、入力欄でのキー無効化、保存失敗時の回答保持、同一idempotency key重送信を確認。実データとAPIは使用せず、一時DBの合成語彙を使用。

## 判断・残課題

answerが評価される前に履歴を保存しない。方向不明の旧historyを新方向の習得根拠として使わない。
