# T-075: Use JST timestamps in generated audio filenames

- Status: Complete
- Priority: P2
- Requirements: DATA-008, DATA-010
- Dependencies: T-073

## Background

Generated audio filenames currently format UTC wall time without marking the timezone. Users in Japan expect the filename timestamp to match the JST creation time shown in the interface.

## Scope

- Included: Newly generated audio filenames encode their timestamp in Asia/Tokyo local time. The suffix remains unique, and file bytes/storage/DB linking are unchanged.
- Excluded: Renaming existing audio files or changing displayed creation timestamps.

## Acceptance criteria

- [x] A known UTC instant is formatted as its corresponding JST timestamp in the filename.
- [x] Verify UTC/JST date conversion and preserve the unique suffix and safe audio naming conventions.

## Test plan

- Unit: Test timestamp conversion using an injected fixed instant and UTC+09:00; existing audio storage tests verify bytes and naming safety.
- Integration: Isolated temporary directory confirms generated audio retains exact content and a JST-formatted name. Run `py -m unittest tests.test_storage_and_pages -v` and full Python suite.
- E2E: N/A: filename formatting has no distinct UI action; generation endpoint behavior is already covered by integration tests.
- Other validation: Run `git diff --check`. The frontend bundle is unaffected by the Python-only filename change.

## Test data / fixtures

- Unit fixture uses a deterministic UTC instant (e.g. 2026-10-25 02:00 UTC -> 2026-10-25 11:00 JST) and temporary audio folder.
- No production files or databases are used.

## Implementation

Format the timestamp using fixed UTC+09:00 to match Japan Standard Time without requiring OS timezone databases; retain the random suffix.
