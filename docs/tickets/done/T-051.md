# T-051: Add per-word and all-vocabulary article generation modes

- Status: Complete
- Priority: P1
- Requirements: GEN-001, GEN-002, FLOW-001, COVER-001
- Dependencies: T-011, T-049

## Background

Filtered vocabulary can currently be used to generate practice text, but there is no user choice between focused one-sentence-per-word practice and a single coherent article that incorporates all selected terms.

## Scope

- Included: Add two selectable generation modes; enforce one target-specific sentence per selected word in sentence mode; generate one cohesive article containing all selected terms in article mode; validate all selected vocabulary in either mode; preserve mode through job payload, resume, result, and saved metadata.
- Excluded: Changing vocabulary filters, selection limits, or audio synthesis behavior.

## Acceptance criteria

- [x] Users can choose `one sentence per vocabulary` or `one article using all selected vocabulary` before generation.
- [x] Sentence mode produces exactly one sentence assigned to each selected vocabulary item and retries missing items through existing coverage handling.
- [x] Article mode sends all selected vocabulary together, produces one cohesive article, and validates every target across the complete article, with a completion pass for missing targets.
- [x] Generation mode is preserved in job payloads, resumed jobs, results, and saved material metadata.
- [x] Existing placeholder/special-character matching rules continue to work; deterministic coverage tests pass.
- [x] Unit, isolated integration, and Playwright tests cover both modes and preserve the existing default flow.

## Test plan

- Unit: Deterministic provider tests assert prompts/schema, one-to-one mapping, article-wide coverage, completion behavior, usage aggregation, and placeholder matching.
- Integration: Temporary-database background-job tests verify mode payload/result progress and saved metadata path.
- E2E: Select each mode, inspect generation request, observe output and auto-save, and verify mode remains selected after restoring a job.
- Other validation: `npm.cmd test`.

## Test data / fixtures

- Synthetic targets `take part`, `comprehensive`, and placeholder `rave about ～`; fixed provider responses for aligned sentences, coherent article paragraphs, missing target completion, and malformed count.
- Temporary test database and mocked browser routes; no production data or paid API.

## Implementation

- Added a mode selector to the overlapping screen. Per-vocabulary generation remains the default; article mode submits the complete selected vocabulary set together.
- Responses API strict JSON schema changes by mode (`sentences` or `paragraphs`). Article-wide target coverage is validated, with one completion request for missing targets.
- Mode is carried in the job payload, checkpoints/results, restored UI state, plan settings, and automatically saved material metadata.
