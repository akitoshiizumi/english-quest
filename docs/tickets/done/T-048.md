# T-048: Show study-set generation failure reasons

- Status: Complete
- Priority: P1
- Requirements: GEN-001, GEN-002, API-002
- Dependencies: T-011, T-024

## Background

When study-set generation fails after partial completion, the UI only displays the completed count and resume action. The API job already contains a useful failure reason and sometimes a list of missing target words, but learners cannot see either. This makes failures confusing and can encourage blind retries.

## Scope

- Included: Show the stored failure reason and missing target vocabulary in the live failed-job state and after restoring a failed job on page load.
- Excluded: Changing target phrase data or generation coverage rules.

## Acceptance criteria

- [x] A failed generation displays completed/total and the server-provided error reason.
- [x] Missing target words are visible when the failed job result includes them.
- [x] The same details remain visible after page reload; resume remains available.
- [x] Missing reason/result fields are handled with a readable fallback.

## Test plan

- Unit: N/A; UI helper is small and covered at the browser boundary.
- Integration: Verify `/api/jobs` returns persisted error and missing target details using an isolated temporary database.
- E2E: Verify visible live failure, restore after reload, and resume action with mocked deterministic job responses.
- Other validation: `npm.cmd test` for full documented suite.

## Test data / fixtures

- Synthetic failed study-set job with 1/2 completed, error `指定語彙を含まない生成文があります: rave about ～`, and missing target `rave about ～`.
- Browser API routes are mocked; tests do not read production vocab.db or call OpenAI.

## Implementation

Added a shared failed-job message formatter; live polling and restored failed jobs now show the API reason and any missing target words, with a fallback when details are absent.
