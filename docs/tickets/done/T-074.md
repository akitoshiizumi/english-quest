# T-074: Show saved material creation timestamps

- Status: ???
- Priority: P2
- Requirements: DATA-009
- Dependencies: T-073

## Background

The saved-material details panel includes a creation-time row, but it has disappeared because the DB API returns `created_at_utc` while the UI formats `created_at`. Learners need the saved material creation time to understand when an item was made.

## Scope

- Included: The saved-material API presents a consistent creation timestamp field to both list/detail consumers, and selecting audio-backed or audio-less materials displays the timestamp in JST.
- Excluded: Changing timestamps for pre-existing DB records whose creation time was never stored.

## Acceptance criteria

- [x] Saved-material and playback detail responses expose the stored `created_at_utc` value under the UI timestamp field without changing its instant.
- [x] E2E asserts that an imported legacy material and a DB-only material show creation time in saved material details; invalid/missing values keep the established fallback.

## Test plan

- Unit: N/A: formatting is presentation-only; the integration suite verifies API field mapping.
- Integration: Isolated HTTP test verifies DB `created_at_utc` maps to API `created_at`. Run `py -m unittest tests.test_http_integration -v`.
- E2E: Select saved materials and confirm creation-time display for legacy-imported and DB-only records. Run targeted Playwright E2E.
- Other validation: Run `npm.cmd run build` and `git diff --check`.

## Test data / fixtures

- Use existing isolated e2e fixtures with explicit deterministic `created_at` values and a DB-only record.
- No production DB or `practice_data` access; E2E server uses its temporary DB and material directory.

## Implementation

The HTTP adapter already exposed timestamps in list records; the playback detail endpoint now also includes `created_at` from `created_at_utc`. The existing JST formatter displays it in both audio-backed and audio-less detail panels.
