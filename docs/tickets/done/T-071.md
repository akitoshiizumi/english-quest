# T-071: Make practice_data JSON files authoritative for material lists

- Status: 完了
- Priority: P1
- Requirements: DATA-008
- Dependencies: T-062, T-060

## Background

The vocabulary-management table and overlap saved-material selector currently include database-only materials. Users see different materials from those stored in practice_data. The user selected practice_data JSON files as the source of truth and asked to show each JSON filename.

## Scope

- Included: Both surfaces list exactly valid JSON files returned from practice_data, with the same order, count, and visible JSON basename. DB-only materials are omitted. Existing DB summaries, archive state, vocabulary links, and actions remain available for matching file-backed records.
- Excluded: Rewriting or deleting practice_data files during list reads; migrating/removing DB-only rows.

## Acceptance criteria

- [x] Both APIs and both screens contain exactly the valid JSON files in practice_data in the same order; DB-only rows are absent and a JSON file missing a DB row is registered idempotently.
- [x] Management rows and overlap options visibly show each JSON filename; both manual refresh buttons reload their list and overlap refreshes after generation; playback and metadata continue for matched file-backed rows.

## Test plan

- Unit: N/A; the file-to-record mapper is an HTTP list orchestration helper, covered through the isolated integration endpoint tests.
- Integration: Exercise both material-list HTTP endpoints against an isolated temp DB and practice_data fixture folder; cover orphan JSON, DB-only row, query, invalid JSON, and filename parity.
- E2E: Open vocabulary management and overlap selector; compare counts/items and confirm the JSON filename is visible on both surfaces, with file-backed playback still available.
- Other validation: TypeScript/Vite build, complete `npm.cmd test`, and `git diff --check`.

## Test data / fixtures

- Synthetic isolated files: a valid JSON+audio fixture, an orphan valid JSON, invalid JSON, and a DB-only material. Never access production practice_data or dataset/vocab.db.


## Implementation

Implemented a shared practice_data-backed list function for both endpoints. JSON files determine membership and order, file-backed DB rows enrich them, and DB-only rows are omitted. Added visible JSON basenames and manual refresh controls; the overlap list also refreshes after audio/subtitle generation and the management list refreshes when its tab is reopened.
