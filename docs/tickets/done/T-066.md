# T-066: Make automatic CEFR assessment resilient to incomplete JSON

- Status: Complete
- Priority: P1
- Requirements: LEVEL-002
- Dependencies: T-018

## Background

Automatic CEFR assessment has failed on a valid API request with an `Unterminated string` JSON parsing error. The current Responses request caps all generated and reasoning output at 160 tokens; a truncated structured response aborts the batch at the current sense.

## Scope

- Included: Increase the CEFR response token allowance and matching preflight budget reserve; detect incomplete and malformed structured responses and report a useful assessment error; record API-reported usage even when an assessment response is invalid; preserve checkpoint behavior so a failed sense can be retried without losing completed senses.
- Excluded: Changing CEFR prompt semantics, model selection, daily budget settings, or the API provider.

## Acceptance criteria

- [x] Automatic and manual CEFR assessments request enough output tokens for the constrained schema and reserve that maximum in automatic budget checks.
- [x] Incomplete or malformed output fails with a clear, actionable message rather than a raw JSON decoder traceback; it does not save invalid levels and records usage reported by the API.
- [x] A failed sense remains eligible for resume while previously completed senses stay checkpointed.
- [x] Existing structured-output success, daily budget protection, and user-visible progress behavior remain intact.

## Test plan

- Unit: Temporary SQLite and deterministic Responses providers cover the increased limit, incomplete response, malformed JSON, no invalid persistence/usage, and retry resume.
- Integration: Existing isolated job/provider integration verifies failed job status and restart from last completed checkpoint.
- E2E: N/A; no UI interaction changes; the existing progress/error UI continues rendering the job's server-side failure message.
- Other validation: `npm.cmd test`, `git diff --check`; no live API call.

## Test data / fixtures

- Existing `DifficultyJobTests` temporary SQLite fixture and injected response provider; synthetic complete, incomplete, and malformed Responses payloads only.
- Never read or modify `dataset/vocab.db`; no paid API calls.

## Implementation

Raised the Responses CEFR output limit from 160 to 512 tokens and aligned automatic preflight cost reservation with the same limit. Incomplete, malformed, and schema-invalid responses now produce an actionable retry error and are never written as CEFR results. API-reported usage from invalid responses is still recorded; the failed job preserves its checkpoint so resuming skips already completed senses. The implementation follows the Responses Structured Outputs guidance that responses can be incomplete when output reaches the token limit: https://developers.openai.com/api/docs/guides/structured-outputs.
