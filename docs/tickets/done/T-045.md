# T-045: Restore study-set vocabulary results with active filters

- Status: Complete
- Priority: P1
- Requirements: FLOW-001, SELECT-001
- Dependencies: T-044

## Background

Study-set planning can return no words for realistic filter combinations. Recent answer filters conflict with the initial unstudied/mastery candidate selection, and limiting the ranked candidates before applying filters can hide matches later in the dataset. The all-categories option is affected as well.

## Scope

- Included: Apply study-set category, mastery, unstudied, recent answer count, and recent accuracy filters independently; apply requested count only after eligibility filtering; return and display eligible filtered words for a category or all categories.
- Excluded: Changes to regular vocabulary practice semantics or ranking weights.

## Acceptance criteria

- [x] Recent answer count/accuracy filters can select words with matching history even when unstudied words are excluded from normal candidates.
- [x] Unstudied and mastery filters remain independently effective when recent history filters are not active.
- [x] With a valid category or all categories and eligible vocabulary, planning returns up to requested count; matching words beyond the former candidate cap are considered.
- [x] UI shows the accurate eligible result count and selected words; empty results are reported only when no words match.

## Test plan

- Unit: Verify selection ranking/filter ordering over synthetic candidates, including eligible matches after the former cap.
- Integration: Temporary SQLite DB through `/api/study-set/plan` with mixed categories, directions, mastery, and answer histories.
- E2E: Plan with all categories and with a category, exercise recent-count/accuracy filters, assert result count and displayed candidates.
- Other validation: `npm.cmd test`, `git diff --check`.

## Test data / fixtures

- Synthetic vocabulary with unstudied, low/high accuracy, short-history, and opposite-direction events; include more candidates than the old cap before an eligible match.
- E2E uses isolated app test database, no production `dataset/vocab.db` and no paid API.

## Implementation

Changed study-set candidate selection to retain studied vocabulary whenever a recent history filter is active, regardless of the include-unstudied preference. Eligibility filters are applied to the complete ordered candidate set before requested count truncation. Existing category and mastery filtering remain in place. Added an isolated HTTP fixture with 512+ candidates and E2E coverage for all categories and a selected category.
