# T-001 既存データの互換性調査

- 状態: 完了
- 優先度: P0
- 要求ID: DATA-001
- 依存: なし

## 目的・実装範囲

既存データの互換性調査を実現し、関連要求を満たす。

## 受け入れ条件

- [x] 全テーブルの型・索引・外部キーと教材ファイルの整合性を読み取りで調べる。
- [x] history各列・日時・方向とsimilarの生成元を、判明事項と不明事項に分ける。
- [x] 既存資産を維持する移行条件をdata-model.mdへ反映する。

## 実装結果

読み取り専用でSQLiteの3テーブル、インデックス、外部キー、件数、サンプル、値の範囲、孤児参照、similarの逆方向レコードを確認。practice_dataのJSON 3件とMP3 3件についてJSON構文と音声参照を確認した。分類列の実データも確認した。

## 確認結果

全テーブルを確認。history 14,085件は旧形式として維持し、方向不明のまま新しい方向別習熟度へ移さない。similar 50,760件は生成条件不明・片方向を含むため、新埋め込みに流用しない。practice_dataのJSON 3件はすべて構文が有効で参照MP3が存在した。語彙の孤児history参照0件、similar両端の孤児0件。

## 判断・残課題

### 判明事項

- vocab 16,920件、history 14,085件、similar 50,760件。cefr_levelは全件未設定。
- `tags`はコース・出典名など混在、`genre_tags`はテーマ分類。カテゴリUIは正規化したカテゴリ・タグ付けが必要。
- historyには方向がなく、score/resultの対応も単純化できない。同じ語彙・session・秒時刻の複数履歴もある。
- similarの逆方向レコードがないものは24,174件。similarityの元モデル等は不明。

### 未確定

- historyのscore、result、appeared_count、correct_countが旧アプリ内でどう算出されたか。
- 旧timestampのタイムゾーン、historyの正確な出題形式。
- similarのモデル・次元・ベクトル入力・対称性を意図したか。
- categoriesを`genre_tags`から導くか、別管理するか。

### 確認方法

読み取り専用SQLite接続とファイル読み取りで調査。元DB・教材ファイルは変更していない。
