# T-006 キー設定と画面案内

- 状態: 完了
- 優先度: P1
- 要求ID: UI-002
- 依存: T-005

## 目的・実装範囲

キー設定と画面案内を実現し、関連要求を満たす。

## 受け入れ条件

- [x] 操作ごとに複数のキーを追加・解除・保存・初期化できる。
- [x] 同一状態での競合を防ぎ、状態が異なる割り当ては許容する。
- [x] 再起動後に設定が復元され、ボタンのキー表示に反映される。

## 必須のテスト確認

- 統合テスト: 実行コマンド、結果、影響を受ける経路を記録する。機能変更では必須。
- E2Eテスト: 受け入れ条件に対応する画面操作シナリオ、実行コマンド、結果を記録する。画面を通る変更では必須。
- 該当しないテスト層があれば、その理由を記録する。
- テストデータ: 使用・追加したfixtureと期待値を記録する。実データ・実APIを使わない。
- テスト未実施や失敗がある間は完了にしない。[テスト方針](../../testing.md)を参照。

## 実装結果

設定画面に操作別の複数英字キーをカンマ区切りで入力するUI、保存と初期値へ復元する操作を実装。設定は `app_settings` にJSONとして保存され、起動後に復元する。アクションボタン表示へ反映。

## 確認結果

`npm test` — 同一状態の競合拒否・異状態の重複許可、キー配列ディスパッチ、設定の再読込をNode/Playwrightで確認。HTTP API経由の設定読み書きは固定DB統合テストの範囲で確認。API・実DB不使用。

## 判断・残課題

短いセットを標準にし、1操作へ複数の英字を割り当てる。Enter/Space標準ボタン操作は残す。
