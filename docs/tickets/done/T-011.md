# T-011 データセットから練習英文を生成

- 状態: 完了
- 優先度: P2
- 要求ID: GEN-001
- 依存: T-004, T-007, T-009

## 目的・実装範囲

データセットから練習英文を生成を実現し、関連要求を満たす。

## 受け入れ条件

- [x] 選定語彙を複数教材に分割し、対象件数・実使用件数・未使用語・使用箇所を保持する。未使用語を補完生成できる（COVER-001）。

- [x] 対象語彙、難易度、テーマ、長さを指定し、生成結果を編集できる。
- [x] 対象語の使用と語形変化の判定規則を決め、不足を知らせる。
- [x] 採用した本文、実際の使用語彙ID、生成条件、モデルを保存する。
- [x] 英語見出しと日本語の意味の検証を保ち、音声作成へ渡せる。

## 必須のテスト確認

- 統合テスト: 実行コマンド、結果、影響を受ける経路を記録する。機能変更では必須。
- E2Eテスト: 受け入れ条件に対応する画面操作シナリオ、実行コマンド、結果を記録する。画面を通る変更では必須。
- 該当しないテスト層があれば、その理由を記録する。
- テストデータ: 使用・追加したfixtureと期待値を記録する。実データ・実APIを使わない。
- テスト未実施や失敗がある間は完了にしない。[テスト方針](../../testing.md)を参照。

## 実装結果

Responses API strict schemaで英文生成。最大10語義ずつに分割して合成し、不足語は不足対象だけ1回補完する。なお不足すれば失敗し、課金usageを保存する。見出し語と一般的な語形を検出し、編集後にも全対象語の存在を検証。長さ・CEFR・テーマを選べる。空行単位でパッセージ教材を保存し、統合本文、語彙使用箇所、採用語彙ID、選定理由、順位、生成条件、モデル、usageを記録。

## 確認結果


npm.cmd test 成功（Python 36件、キーボード3件、Playwright 7件）。固定providerで10語上限の分割、語形変化、欠落語補完、usage集計、対象語なし失敗を確認。HTTP integrationでジョブ/usage/前回条件、Playwrightで選定・編集・複数パッセージ保存・語彙対応・音声作成・履歴から再開・語彙学習へ戻る動線を確認。APIは固定fixtureのみ。

## 判断・残課題

保存は統合教材1件と空行区切りの各パッセージ教材を記録し、各パッセージで実使用された語彙IDだけを結ぶ。音声生成は画面上の統合本文から行う。目標語彙が多いと生成文が長くなるため、利用者が編集・選定してから音声を作る。
