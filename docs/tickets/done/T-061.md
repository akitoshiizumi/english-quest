# T-061: Add AI summaries to saved material metadata

- Status: Done
- Priority: P1
- Requirements: DATA-007, API-001, API-002
- Dependencies: T-028, T-050, T-060

## Background

Saved materials have no concise description in their metadata, so learners must reopen the full text to recall what a material covers.

## Scope

- Included: Provide an explicit per-material AI summary action in material management; store summary, model, prompt version, and generated timestamp in metadata_json; show the summary and allow regeneration; record API usage and show actionable failures.
- Excluded: Automatic paid API calls when listing or creating materials; bulk summarization; editing summary text by hand.

## Acceptance criteria

- [x] Each saved material row shows its AI summary or an explicit not-yet-generated state, and offers generate/update without calling the API on page load.
- [x] A successful generation stores summary and provenance in metadata_json, updates the visible row, and records model, token usage, and estimated cost. Editing the material title or text invalidates a summary generated from the previous content.
- [x] Missing API key, API failure, malformed/empty output, and unknown material ID produce clear errors without overwriting an existing summary.

## Test plan

- Unit: Test response parsing and validation with deterministic provider fixtures.
- Integration: Isolated HTTP/SQLite tests verify Responses request, metadata persistence, usage logging, existing metadata preservation, failure behavior, and not-found handling; no paid API.
- E2E: In material management generate a summary, verify it is displayed, update/regenerate, verify failure messaging, and confirm page listing makes no generation request.
- Other validation: `npm.cmd test`, `git diff --check`; official Responses API guidance reviewed.

## Test data / fixtures

- Synthetic material with existing metadata fields and fixed summary Responses API success, malformed output, empty output, missing-key, and API-failure fixtures in temporary test storage.
- Tests must not access production `dataset/vocab.db`, `practice_data`, or paid APIs.

## Implementation

Added a Responses API summary generator using the configured text model and a strict JSON schema. Saved material management now shows each summary, provides explicit generate/update actions, discloses that API usage is billable, and never generates summaries while loading the list. Summaries and model/prompt/timestamp provenance are merged into the existing metadata JSON, API jobs and usage/cost are recorded, and title/text edits remove stale summaries. Missing keys and failed or malformed responses keep existing metadata unchanged.
