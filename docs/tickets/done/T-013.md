# T-013 苦手語彙から教材作成・音声練習までの統合

- 状態: 完了
- 優先度: P2
- 要求ID: FLOW-001, SELECT-001, COVER-001
- 依存: T-008, T-011, T-012

## 目的・実装範囲

「カテゴリAの覚えていない語彙上位50件」を起点に、文章・音声を作り、オーバーラッピングを開始できるようにする。

## 受け入れ条件

- [x] カテゴリ、方向、件数、難易度、未学習語を含めるかを指定し、前回条件を再利用できる。
- [x] 選定語彙と選出理由を確認し、生成・練習まで進める。対象不足・0件を案内する。
- [x] 50件は語彙数として扱い、複数教材に分かれても一つの練習セットとして開始・再開できる。
- [x] 対象件数、使用件数、未使用語、使用箇所を示し、必要なら補完生成できる。
- [x] 対象語、選定条件・順位、教材との対応を保存し、語彙の状態が後で変わっても生成時の条件を確認できる。
- [x] APIの費用目安と進行を示し、生成失敗時に完了済みの教材を再課金して作り直さない。
- [x] 音声練習の記録から対象語の語彙復習へ移れる。音声練習だけで習得済みにはしない。

## 実装結果

weakness-v1でカテゴリ・方向・件数・CEFR・未学習語の条件に合う弱点語を選び、順位と理由を表示。前回条件をDBへ保存。最大50語を対象に英文を最大10語義ずつ生成し、使用箇所・対象/使用/未使用数を保持して教材セットとして保存。開始前に英文・Realtime音声・文字起こしの概算を表示。途中失敗では完了済みチャンクをcheckpointし、ページ再読込後も同一ジョブから再開。教材一覧からオーバーラッピングを始め、音声履歴から復習予定画面に戻れる。音声練習だけでは語彙習得イベントを作らない。

## 確認結果

`npm.cmd test` — Python 36件、キー操作3件、Playwright 7件すべて成功。temporary DBと固定Responses providerで方向別弱点順位、条件復元、job checkpoint/retry時の未完了分のみ生成・課金、教材と語彙使用箇所の対応を確認。Playwrightで選定→生成→編集→複数教材保存→オーバーラッピング再生・活動記録→統計/復習導線を確認。実データ・実API不使用。0件・対象不足の表示は空選定統合テストで確認。

## 判断・残課題

教材分割は空行区切りで統合教材と個別パッセージ教材を併記する。再開時に前回完了チャンクを再生成しない。選定上限は要求例に合わせ50語。語彙の習得状態は音声練習から変更しない。
