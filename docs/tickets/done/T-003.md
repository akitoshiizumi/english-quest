## 目的・実装範囲

機能分割と共通操作の基盤を実現し、関連要求を満たす。

## 受け入れ条件

- [x] HTTP・サービス・保存処理と画面の責務を分割する。
- [x] 操作IDとキー配列の共通ディスパッチを用意する。
- [x] 既存の教材読み込み・音声再生・字幕追従を確認し、変更範囲を記録する。

## 必須のテスト確認

- 統合テスト: 実行コマンド、結果、影響を受ける経路を記録する。機能変更では必須。
- E2Eテスト: 受け入れ条件に対応する画面操作シナリオ、実行コマンド、結果を記録する。画面を通る変更では必須。
- 該当しないテスト層があれば、その理由を記録する。
- テストデータ: 使用・追加したfixtureと期待値を記録する。実データ・実APIを使わない。
- テスト未実施や失敗がある間は完了にしない。[テスト方針](../../testing.md)を参照。

## 実装結果

`english_overlap/http.py`へHTTP処理、`storage.py`へ教材ファイル処理、`pages.py`へページ・静的ファイル配信を分割した。画面操作は `static/learning.js` と `static/overlap.js`、キー操作は汎用ディスパッチャー `static/shortcuts.js` に分離した。OpenAI WebSocketライブラリを音声要求時の遅延importへ移し、DBなしの画面テストで import 可能にした。

## 確認結果

`npm test` — Python統合テスト、キーディスパッチテスト、Playwright E2Eがすべて成功。E2Eで合成保存教材を読み込み、音声を再生し、字幕のactive語を確認。新規教材から音声生成・再生・字幕追従・再生時間記録までの経路も固定API応答で確認。既存MP3そのものの音声品質は再生成なしで変わらないため、品質測定は行っていない。

テストデータは `tests/e2e_server.py` の一時DB、合成語彙、合成1秒WAV。実DB・practice_data・実APIはテストで開かない。

## 判断・残課題

表示ボタンとキー操作を共通操作に接続し、デフォルトのA/U/S/Iは状態ごとに作用する。既存保存データの音声・字幕読み込み経路は維持した。
