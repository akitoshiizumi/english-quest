# T-029: 語彙管理一覧にソートと50件ページングを追加

- Status: Complete
- Priority: P1
- Requirements: DATA-003, DATA-005
- Dependencies: none

## Background

語彙管理は一覧の並べ替えやページ移動がなく、語彙が増えると対象を探して編集しづらい。

## Scope

- Included: 安定した列ソート、1ページ50行、件数表示、検索・アーカイブ条件を維持したページ移動。
- Excluded: 一括編集、語彙データの一括削除。

## Acceptance criteria

- [x] 英語見出し、日本語の意味、品詞、タグ、CEFRを昇順・降順でソートでき、現在の列と方向を示す。
- [x] 1ページ50行で前へ/次へ/先頭/末尾へ移動でき、先頭・末尾では該当操作を無効化する。
- [x] 現在範囲（例: 51–100）とフィルター後の総件数を表示する。0件と最終ページ端数を正しく扱う。
- [x] ページ変更後も検索語とアーカイブ条件を保つ。検索条件やソート列を変えた場合は先頭ページに戻る。
- [x] 同じ値がある列でもページ間で行が重複・欠落しないよう安定した第2ソートキーを用いる。ユーザー入力をSQLの列名に直接使わない。
- [x] デスクトップでは読みやすい表、狭い画面ではカードまたは横スクロールで主要情報と操作を利用できる。
- [x] 行を選ぶと英語見出しと日本語の意味がすぐ見つかり、既存の編集・アーカイブ操作へ進める。

## Test plan

- Unit: ソート順、同値時の安定順、件数0/1/50/51/100/端数、ページ境界。
- Integration: 一時DBで検索・ソート・ページング・編集後の整合性を確認。
- E2E: 検索、ソート方向切り替え、ページ移動、条件維持、編集/アーカイブ、狭い画面を確認。
- Other validation: `npm test`。

## Test data / fixtures

- 英語・意味・品詞・タグ・CEFRが異なる合成語彙を少なくとも125件作り、同値列、空値、アーカイブ済み、ページ端を含める。本番DBは使わない。

## 表示案

- デスクトップはコンパクトな表を使い、ソート可能な列に方向アイコンを付ける。
- 表の上部に絞り込み件数と現在範囲、下部にページ移動を配置し、ページ移動時も条件を維持する。
- 画面幅が狭い場合は、横スクロールで操作列を失わせるより、英語見出しを主見出し、日本語の意味・品詞・CEFRを補助情報にしたカード表示を優先する。
- 語彙数が多い利用者向けに、現在の検索条件をクリアする操作と空結果の案内を置く。

## Implementation

語彙管理APIに50件単位のサーバー側ページング、フィルター後の件数、許可リストによる列ソート、安定した語彙ID/語義順タイブレークを追加。UIにソート状態、範囲/件数、先頭/前/次/末尾操作を追加。狭い画面では既存の表スクロールを利用し、見出しを固定。
