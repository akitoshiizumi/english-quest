# T-077: Index all missing vocabulary similarity embeddings

- Status: Complete
- Priority: P1
- Requirements: none (existing vocabulary similarity behavior; this ticket completes the index workflow)
- Dependencies: none

## Background

The similarity index screen currently indexes only one batch of 100 senses per click. Users with more missing senses must repeatedly click and monitor the status, so the requested "index all missing" action is not fulfilled.

## Scope

- Included: Provide one action that indexes every currently missing eligible sense in repeatable batches; show total progress and refresh the remaining count; preserve completed batches and allow retry after a failed batch.
- Excluded: Changing similarity semantics, embedding model, cost estimation, or the server batch-size limit.

## Acceptance criteria

- [x] One click processes successive batches until the server reports zero missing senses.
- [x] The UI displays indexed/initial total progress while running and refreshes the estimate on completion.
- [x] A zero-progress response with remaining work stops safely; a failed batch leaves prior batches saved and the UI reports remaining work for retry.
- [x] The action is unavailable when no eligible senses are missing and cannot be started twice concurrently.

## Test plan

- Unit: `py -m unittest tests.test_embeddings -v`; synthetic isolated DB verifies sequential 100-item batches cover all remaining senses.
- Integration: `py -m unittest tests.test_http_integration -v`; existing API boundary tests remain green; no paid API calls.
- E2E: `node --test --test-concurrency=1 tests/e2e_learning.cjs`; mock plan/index responses and verify repeated calls, visible progress, completion, and failure/retry state.
- Other validation: `npm.cmd run build`; `git diff --check`.

## Test data / fixtures

- Add 205 synthetic senses to a temporary SQLite DB and use a deterministic fake embedding provider; expect three calls and 205 indexed records.
- Browser E2E intercepts plan/index endpoints with deterministic response sequences; never access `dataset/vocab.db`, `practice_data`, or a paid API.

## Implementation

The UI now requests consecutive 100-sense batches until the server reports zero remaining senses. A progress bar and live text show indexed totals; completion refreshes the cost estimate. Duplicate starts are blocked. On API failure the UI rechecks the remaining count and enables retry; successful server batches remain cached in SQLite. A zero-progress response with outstanding work terminates safely.

## Limitations

The request remains synchronous from the browser's perspective, with progress refreshed after each server batch. Closing the page interrupts the loop; completed batches are durable and a later click resumes from remaining senses.
