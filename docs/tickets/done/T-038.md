# T-038: Stabilize same-second vocabulary answer order

- Status: Complete
- Priority: P1
- Requirements: VOC-002
- Dependencies: T-032

## Background

The full suite exposed a pre-existing intermittent failure in the latest-incorrect filter. Answer events had second-resolution timestamps and random UUID tie breaking, so rapid answers in the same second could appear out of order.

## Scope

- Included: Microsecond timestamps for new vocabulary answers and insertion-order tie breaking for existing same-time records in practice filters, history, and statistics.
- Excluded: Rewriting historical event timestamps.

## Acceptance criteria

- [x] Recent and latest answer filters use insertion order if timestamps tie.
- [x] Answer history and dashboard calculations use the same stable order.
- [x] An integration fixture forces tied timestamps and the full suite passes.

## Test plan

- Unit: N/A; this is SQL query ordering verified through the HTTP integration boundary.
- Integration: Force answer timestamps to tie in `test_recent_accuracy_all_incorrect_and_session_count_limits` and verify latest-incorrect/accuracy results.
- E2E: Existing practice filters in the full Playwright suite; no separate UI change.
- Other validation: `npm.cmd test`, `git diff --check`.

## Test data / fixtures

- Existing temporary SQLite HTTP fixture, with tied timestamps added explicitly.

## Implementation

New answer events use microsecond timestamps. Queries order tied timestamps by SQLite insertion row ID instead of random event IDs. No schema or historical data migration is needed.
