# T-062: Make the saved-material lists show the same materials

- Status: 作業中
- Priority: P1
- Requirements: DATA-008
- Dependencies: T-050, T-060

## Background

The overlap saved-material selector reads JSON files from the materials folder, while vocabulary management reads rows from the materials database table. Legacy files and text-only database materials therefore appear in only one list, so the number of listed materials differs.

## Scope

- Included: Make both screens list the same complete set of materials from the database; idempotently register legacy saved JSON files that are not yet represented in the database; show text-only database materials in the overlap selector with a clear no-audio state; display the item count in both screens.
- Excluded: Changing vocabulary links or summary content; deleting, moving, or rewriting existing saved JSON/audio files.

## Acceptance criteria

- [x] With no active search filter, the overlap saved-material selector and vocabulary management list show the same material rows and the same total count.
- [x] Existing saved JSON files missing from the database are registered idempotently without modifying or deleting their files; repeated list requests do not create duplicates.
- [x] Database materials without saved audio remain visible in both lists and can load their text into the overlap editor with audio controls unavailable and a clear message.
- [x] File-backed material playback, archived materials, list export, vocabulary links, and existing create/edit/delete operations continue to work.

## Test plan

- Unit: Test saved-file registration is idempotent, preserves file metadata and references, and leaves existing managed rows unchanged.
- Integration: Use an isolated DB and synthetic materials folder to verify list synchronization, shared counts, empty/text-only materials, archived status, and repeated reads.
- E2E: Verify both screens show the same row count/materials, text-only material handoff, file-backed playback, and list behavior with an empty search.
- Other validation: `npm.cmd test`, `git diff --check`.

## Test data / fixtures

- Synthetic legacy saved JSON/audio fixtures, already-managed file-backed material, text-only DB material, and archived material.
- All files and database state use isolated temporary storage; never access production `dataset/vocab.db` or `practice_data`.

## Implementation

Implemented a DB-backed saved-material endpoint and idempotent legacy JSON registration. Both interfaces show the unfiltered canonical material set and total count. Selecting a row without an existing audio artifact loads its text and disables playback controls. Legacy JSON/audio files are not modified during synchronization.
