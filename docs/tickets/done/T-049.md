# T-049: Handle vocabulary placeholders in generated sentences

- Status: Complete
- Priority: P1
- Requirements: GEN-001, GEN-002, COVER-001
- Dependencies: T-011, T-048

## Background

Vocabulary entries can include suffix placeholders such as `～` or `~` to indicate an open phrase (for example `rave about ～`). Generation currently asks for the full literal entry, and coverage validation treats the placeholder as text. Failed-job metadata also stores the error message itself as `missing_targets`, causing the UI to repeat the error as a supposed vocabulary item.

## Scope

- Included: Define and document matching behavior for trailing phrase placeholders, pass that behavior into the generation prompt, validate the phrase stem in generated English, store actual missing vocabulary as structured data, and display legacy/new failure metadata correctly.
- Excluded: Editing existing dataset entries or changing completion/retry limits.

## Acceptance criteria

- [ ] Entries ending in supported placeholder markers (`～`, `〜`, `~`, `…`, `...`) generate and validate by their English phrase stem; markers are described as placeholders in the prompt.
- [x] Punctuation and regex metacharacters in non-placeholder vocabulary are treated literally in coverage matching.
- [x] Failed jobs store missing vocabulary as structured target names, separate from the explanatory error.
- [x] Current and legacy failed jobs display the error once and show target names only when available.
- [x] Tests cover prompts, exact offsets, placeholder entries, regex punctuation, and UI rendering.

## Test plan

- Unit: Generation and vocabulary matcher tests with deterministic provider.
- Integration: Failed synthetic generation stores error and structured missing-target list through job API in a temporary DB.
- E2E: New structured and legacy string failure payloads render the reason without falsely duplicating it as a target; existing resume flow remains available.
- Other validation: `npm.cmd test`.

## Test data / fixtures

- Synthetic targets: `rave about ～`, `I'm about to ~`, `C++`, `a+b`, and generated English sentences that include/exclude the literal phrase stems.
- Deterministic provider fixtures; isolated temporary database; mocked browser API routes; no production data or paid APIs.

## Implementation

Updated generation prompts to describe recognized suffix markers as open slots and coverage matching to validate the English phrase stem. Coverage failures now keep target names in a structured list separate from the error text. Legacy jobs that copied their error into `missing_targets` show the error once without a false target label.

## Limitations

Placeholder matching uses the English phrase before a recognized trailing placeholder. It cannot infer a missing complement or repair a semantically incorrect generated sentence.
