# T-018 CEFR難易度の自動評価

- 状態: 完了
- 優先度: P1
- 要求ID: LEVEL-001, LEVEL-002, API-002
- 依存: T-004, T-009

## 目的

利用者が一括評価を手動で開始しなくても、語彙データセットの未評価語義をバックグラウンドでCEFR評価する。

## 受け入れ条件

- [x] 新規語彙追加後、または起動後に未評価語義を検出して自動評価ジョブへ登録する。
- [x] 評価処理はバックグラウンドで実行し、画面を閉じても進行・結果・失敗状態を保持する。
- [x] API費用・件数の上限を設定でき、上限到達時は停止して状況を知らせる。
- [x] 失敗・レート制限から再開し、完了済み語義を再評価・再課金しない。
- [x] 手動設定済みの難易度は維持し、根拠・モデル・日時・使用量を保存する。
- [x] 自動処理の有効/停止と進行状況をデータベース管理または語彙管理画面から確認できる。
- [x] API利用なしの起動・語彙練習を妨げず、APIキーを画面へ返さない。

## テスト

固定Responses providerで、新規追加時のキュー登録、再起動後の継続、重複登録防止、上限停止、pause/resume、手動値保持、usage記録を統合テストする。Playwrightで自動評価状態と停止・再開操作を確認する。有料APIは使用しない。

## 設計メモ

自動実行はユーザーの操作なしで課金が発生するため、1回あたり件数・日次費用上限・一時停止手段を提供する。既定上限は実装時に既存料金設定と合わせて決める。


## 実装・検証結果 (2026-10-24)

- 起動時と語彙追加登録後に未評価語義を自動ジョブに登録。APIキーなしはキューで待機し、語彙練習・既存教材の操作は通常どおり使用できる。
- データベース管理に自動評価の有効化、一回の件数（1〜100、初期10）、日次上限（初期$0.05）の設定、進捗・使用額・停止・再開表示を実装。対応モデルは`OPENAI_TEXT_MODEL`に従い、実キーは返さない。
- 自動評価は1ジョブ100語義まで。Responses APIのStructured OutputsでCEFRをA1〜C2に制限し、`max_output_tokens: 160`で生成上限を設定。出力上限と語義入力長上限から事前予算し、日次残額が足りない場合は次のリクエスト前に保留する。
- 完了済み語義IDとAPI usageをチェックポイント保存。レート制限等は失敗として保持し、再開時に完了分はスキップする。手動評価済み語義は自動更新しない。
- 統合: `py -m unittest tests.test_difficulty tests.test_http_integration -v` 成功 (16件)。起動時の既存キュー再開、費用上限の事前停止、失敗・再開、使用量、登録・重複防止、キー不在でのキューを合成DBで確認。
- E2E: `npm.cmd run test:e2e` 成功 (Playwright 12件)。起動キュー、設定の停止・再開、自動評価の表示と手動評価を確認。
- 全体: `npm.cmd test` 成功 (Python 42件、キーボード3件、Playwright E2E 12件)。型検査/Viteビルド成功。`py -m compileall -q english_overlap tests`成功。自動テストは一時DB、固定providerとキー空で実行。実APIなし。
- API確認: 2026-10-24、[Responses Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)と[Responses API参照](https://developers.openai.com/api/reference/resources/responses/methods/create)を確認。現行`TEXT_MODEL`設定を使い、APIやモデルIDは変更しない。
