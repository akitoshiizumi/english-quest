# T-080: Show the nearest vocabulary beside preview candidates

- Status: Complete
- Priority: P1
- Requirements: none (vocabulary preview explainability)
- Dependencies: T-078

## Background

Vocabulary preview says whether an item is an addition candidate or an exact match, but does not show which existing indexed words are most similar. Showing up to three nearby words and their cosine scores helps users judge the proposed vocabulary in context.

## Scope

- Included: Return the three nearest distinct indexed headwords for each preview assessment and show them after the existing status label; retain exact-match and threshold results while using an exact-safe top-three search.
- Excluded: Changing the threshold, the inclusion rule, embedding model, or adding a third-party vector search dependency.

## Acceptance criteria

- [x] Each preview row shows up to three distinct nearest vocabulary headwords with exact cosine scores after its “追加候補” / “完全一致” / threshold status; fewer than three available matches show only those found.
- [x] The three results are the true nearest indexed headwords, even when all scores fall below the inclusion threshold; ties are deterministic and multiple senses of one headword do not duplicate the display.
- [x] Similarity threshold exclusion, exact match behavior, safe pruning, and the HTTP response's omission of raw embedding vectors remain intact.

## Implementation

Batch comparison now returns up to three distinct nearest headwords and exact cosine scores. The scorer processes rows in upper-bound order and stops only after the remaining Cauchy-Schwarz bounds cannot beat the current third result or reach the exclusion threshold. Preview rows append these words after the existing candidate status.

## Limitations

The nearest three are selected from vocabulary senses with matching embedding model and dimensions, then deduplicated by normalized headword. Exact headword matches short-circuit embedding lookup and have no nearest-match list.
