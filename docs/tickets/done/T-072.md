# T-072: Make saved JSON authoritative for title and AI summary

- Status: 完了
- Priority: P1
- Requirements: DATA-007, DATA-008, API-001, API-002
- Dependencies: T-061, T-063, T-071

## Background

For file-backed saved materials, practice_data JSON and the associated database row can contain unrelated titles and bodies. The summary action currently sends the database title/body to the AI and stores the result only in DB metadata. Regenerating therefore repeats the mismatch and the overlap screen can show the wrong summary.

## Scope

- Included: Treat JSON title/body/AI summary/provenance as canonical for file-backed materials; generate title and summary from that exact JSON body; persist both and provenance into the JSON and mirror them to SQLite; synchronize DB material title/body/summary metadata from JSON on reads; make explicit management title/body edits update the JSON and invalidate stale summary/audio timings.
- Excluded: Bulk API calls or automatic paid summarization; rewriting production files during list reads; repairing existing production material content without an explicit user action.

## Acceptance criteria

- [ ] A summary update uses only the matching JSON text, generates a title and Japanese summary, and writes both plus model/prompt/timestamp provenance atomically to that JSON; the visible title/summary and DB mirror then agree.
- [ ] If a DB row contains unrelated stale text/title/summary, list reads display and reconcile from JSON; manual title/body edits update JSON, invalidate its old AI summary, and body edits detach stale audio timing without deleting audio files.
- [ ] Missing/invalid JSON or API failure does not overwrite existing JSON summary/title; database-only materials cannot be summarized as saved files; usage/cost and existing playback/summary metadata remain correct.

## Implementation

File-backed material titles, article text, AI summaries, and summary provenance now come from `practice_data` JSON. The explicit summary action sends only the matching JSON article text to the Responses API, generates a title and Japanese summary, and atomically saves both with provenance to that JSON before synchronizing the SQLite projection. Material reads reconcile stale database metadata from JSON. Editing title/body updates JSON; body edits invalidate the previous summary and detach stale audio timing while preserving the audio file.

## Limitations

Existing mismatched production summaries are not automatically regenerated; users must explicitly choose AI summary update. The database projection self-corrects from JSON when material lists load.
