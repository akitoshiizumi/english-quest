# 構成方針

PythonサーバーとSQLiteを維持し、ブラウザGUIはReact + TypeScriptで構築する。Viteで作った静的成果物を既存のPythonサーバーから配信し、通常利用時にNode.jsサーバーを必須にしない。生成済み成果物をGit管理し、フロントエンド依存と型検査・ビルド手順はnpm lockfileとpackage scriptsで固定する。移行中は既存API契約を保ち、機能単位で画面を置き換える。

```text
React画面・機能タブ・共通操作
    ↓ HTTP
ルーティング・入力検証
    ↓
学習 / 教材 / 取り込み / 統計 のサービス
    ↓
DBアクセス・ファイル保管 / OpenAI接続
```

- HTTP処理からSQLや生成プロンプトを分離する。
- Reactの画面は機能別に分け、状態管理・APIクライアント・共通UIを再利用する。大きな単一コンポーネントに機能を集約しない。
- タブ構成はオーバーラッピング、語彙練習、語彙管理、語彙追加、データベース管理とする。語彙教材生成は語彙練習内の条件指定として扱う。
- 学習イベントを記録の正本とし、復習予定・統計はその情報から計算する。
- OpenAI接続は用途別の共通窓口を設ける。APIキーはサーバー環境だけで保持する。
- 長い生成・埋め込み・難易度判定は状態付きジョブにする。画面で進行と失敗を確認でき、再試行・中断・再開ができる。
- API通信中にDBの書き込みトランザクションを保持しない。SQLiteの並行アクセスと二重送信を考慮する。
- 既存HTTP経路・教材再生を保ちながら新機能を接続する。API経路とスキーマの詳細は実装チケットで確定する。

品質確認はチケットの受け入れ条件を基準にする。特に移行・復元、二重記録防止、状態ごとのキー操作、類似除外の誤判定を確認する。APIを使う評価はローカルの契約確認と有料の実呼び出しを区別して結果に残す。

チケットごとの自動テスト階層、テストデータと実データの分離は[テスト方針](testing.md)を適用する。テストDB初期化とE2Eの実行方法をT-002、T-003で決める。
